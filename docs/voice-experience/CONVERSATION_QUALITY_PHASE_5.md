# Phase 5: synthetic feedback evaluation library

The versioned library `evals/conversation-feedback.v1.mjs` contains 28 entirely invented cases: eight conversation-detector cases and twenty bilingual summary cases. Five summary discrepancies each have English and Spanish defect/control pairs. These test latest corrections, missing unresolved questions, unsupported claims, suggestions turned into commitments, and lost uncertainty. Conversation cases cover repetition, clarification, Spanish drift, English official labels inside Spanish, incomplete captures and successful versus failed topic changes.

Run `npm run eval:feedback` for the eight offline checks against the real conversation analyzer. The twenty semantic summary cases remain explicitly not run. No API credentials or provider calls are used. Results go to `output/feedback-evaluation.json`, containing case IDs and metrics rather than transcripts or summary text.

For semantic checks, explicitly run `npm run eval:feedback -- --live` with OPENAI_API_KEY in the environment. This makes twenty sequential bounded requests using the production summary-review adapter and configured summary model. Each request inherits its 12-second timeout, 700-output-token ceiling and disabled provider storage. No environment file is automatically read. Provider failures count as failed cases, never successful reviews. The report records model, timestamp, missing categories, unexpected categories and category-level precision/recall; an empty denominator is null, not perfect performance. A nonzero exit code indicates failures.

Use phase 4 reviewed recurring categories to choose new invented scenarios or expand existing ones. Counts of automated flags alone do not demonstrate confirmed defects. No production transcript, user quotation, identifier or private detail should be copied into the catalog. This phase establishes reusable examples; it does not claim examples were derived from production records that have not been inspected.

Before phase 6 prompt changes, preserve the baseline report, rerun the same cases against the proposed configuration, examine misses and false positives separately in each language, and review failures. Synthetic results cannot establish pronunciation, audio continuity, real-user comprehension or policy accuracy. The optional provider run has not been executed as part of local implementation. Nothing automatically updates deployed prompts or trains a model.
